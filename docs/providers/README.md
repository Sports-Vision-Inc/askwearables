## Feature flags

`ConnectorRegistry` (`src/registry.ts`) ships every provider OFF (`DEFAULT_FLAGS`). The host turns providers on with `parseFlags(env.CONNECTOR_FLAGS)`, for example `{"oura":{"enabled":true,"tier":"sandbox"}}`.

Strava cannot be enabled without a `writtenApproval` reference. Its connector also refuses to authorize, backfill or take webhooks without one.

## Terms flags and why

| Provider | Flags | Reason (see the provider file) |
|---|---|---|
| Strava | `no_ai`, `no_intermediary`, `display_to_user_only` | API Policy 2026: §5.3 bans the operation of AI apps, including context-window ingestion. §5.16 bans aggregators and MCP servers. Data may be shown to the user only. |
| Oura | `no_ai`, `no_intermediary` | API Agreement (effective 2026-06-08), §4(d): no providing data to any AI model except through Oura's own MCP server. The "Aggregator" rules also apply. This conflicts with the product's purpose and needs a legal reading before enabling. |
| WHOOP | none (pending) | Terms §4.2.3 ban using data to create, train, test or improve AI. Inference is not named. Get WHOOP's position in writing. |
| Google Health | none | Limited Use policy: transfers only for user-facing features with consent. There is no explicit AI clause. CASA assessment needed past 100 users. |
| Garmin | none | Agreement §15.10 (2026 text) requires an AI Transparency Statement and explicit consent. §5.2(o) limits passing data to unapproved third parties. |
| Polar | none | AI is not mentioned. Credit "Polar Ecosystem" wherever data is displayed. Explicit user permission is needed before data goes to external sources. |
| Open Wearables | none for the adapter | Upstream terms still apply. The adapter drops every record whose upstream provider is Strava. |

## Rules every connector follows

- Webhooks are verified, return quickly, and become `SyncJob`s for a queue. Signature schemes:
  - Oura: uppercase hex HMAC-SHA256 of timestamp + body.
  - WHOOP: base64 HMAC-SHA256 of timestamp + body.
  - Polar: hex HMAC-SHA256 of the body.
  - Google: Authorization secret plus a Tink ECDSA P-256 signature.
  - Open Wearables: Svix.
  - Garmin and Strava sign nothing, so they rely on a secret URL token (and Strava's `subscription_id`). Garmin `callbackURL`s are only fetched on `apis.garmin.com`.
- HTTP 429 (and 502/503/504) is retried with exponential backoff that honours `Retry-After` (`src/http.ts`).
- Refreshes are serialized per user (`src/refresh.ts`). WHOOP invalidates the old access token on refresh. Oura, Garmin and Strava rotate refresh tokens. Across Worker isolates, run refresh inside the user's Durable Object.
- `external_id` is derived from the provider's record id, so re-ingest is idempotent.
- Vendor scores are emitted as `vendor_score` records only. These include readiness, recovery, strain, sleep scores, Nightly Recharge, ANS charge and Garmin stress.
- Fixtures under `packages/connectors/test/fixtures/` are hand-written and scrubbed to match the documented shapes. They contain no real data or credentials.
